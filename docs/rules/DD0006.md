# DD0006: Keep public types under the assembly's root namespace

|  |  |
| --- | --- |
| **Id** | `DD0006` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `NamesAndNamespaces.RootNamespaceEqualsAssemblyName` |
| **Introduced in** | unreleased |

## Principle

One assembly, one root namespace, one name. A public type outside it is a second package hiding
inside the first, and the only way to find it is to read every file.

## What the rule checks

Every public type's namespace is the assembly name, or begins with the assembly name followed by a
dot. A public type in the global namespace is reported too.

The prefix match requires the dot: for assembly `Sample.Layer1`, the namespace `Sample.Layer10` is
not under it. Matching without one would let a neighbouring assembly's namespace pass.

Nested types are reached through the type that contains them, so a public type nested in a
misplaced public type produces one finding rather than two.

## Configuration

None. The root namespace is the assembly name by definition of the rule; a project that wants a
different one is asking for the assembly to be renamed.

## False-positive story

Tier 1 and decidable: it compares two strings that are both in the compilation.

Only public types are checked, so internal helpers may live anywhere. That is the rule's scope
rather than a gap: the shape being protected is the package's surface.

The case that looks like a false positive and is not: a project whose `RootNamespace` MSBuild
property differs from its `AssemblyName`. The rule reads the assembly name, because that is what a
consumer sees. If the two should differ, that is a decision, and `[DesignDecision]` on the type is
where it is recorded.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0006
```

No fix is registered. Moving a public type under the root namespace is a rename of that type's full
name, which is a breaking change for every consumer of the assembly; deciding whether the type moves
or the assembly does is the judgement the rule is asking for.

## Violating example

```csharp
// in assembly Sample.Layer1
namespace Other.Place
{
    public sealed class Thing { }
}
```

```text
DD0006: public type 'Thing' is in namespace 'Other.Place', which is not under this assembly's root namespace 'Sample.Layer1'.
Decide: move it under 'Sample.Layer1', or move it to the assembly whose name matches the namespace it belongs in | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
// in assembly Sample.Layer1
namespace Sample.Layer1.Ingest
{
    public sealed class Reader { }
}
```
