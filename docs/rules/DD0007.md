# DD0007: Cite a decision the ledger produced, with its required arguments

|  |  |
| --- | --- |
| **Id** | `DD0007` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `DecisionsAsTypes.AttributeArgumentsMustBeGenerated` |
| **Introduced in** | unreleased |

## Principle

A citation is worth checking only because the compiler checks it. A `Type` argument that resolves to
a type somebody wrote by hand says exactly what a string citation said: that somebody typed
something.

## What the rule checks

The four citing attributes — `[Contract]`, `[DomainModel]`, `[HotPath]`, `[DesignDecision]` — and
three things about each:

**The `decision` argument is a generated decision type.** It must be a `typeof` expression, and the
type it names must be one this generator emitted. Three things are checked, all required:

- **Shape.** A static class nested in a static class under `DecisionDriven.Ledger.*`, carrying `Id`,
  `Key` and `Namespace` constants, inside a set class carrying `SetId`.
- **The generated-code marker.** `[System.CodeDom.Compiler.GeneratedCode("DecisionDriven.Analyzers",
  "<version>")]`, which the generator puts on every set and decision type. It is the BCL's own
  attribute rather than one of this package's: adding an attribute here would extend ADR-A07's
  attribute table, which is a decision, and reusing the one every generator already emits is not.
  The version argument is recorded but not checked — it says which version emitted the file, which
  is not a thing a citation can be right or wrong about.
- **Generator provenance.** The declaring syntax tree's path is the synthetic one Roslyn gives
  generator output: `DecisionDriven.Analyzers/DecisionDriven.Analyzers.DecisionLedgerGenerator/<hint>.g.cs`.

Shape alone is not the test, and neither is the marker. Both are text, and anyone can write text.
The path is a compiler input rather than a file, and that is what makes it the signal that counts;
the marker is required alongside it because a file that does not claim to be generated is not one.
A type with all three written by hand is impossible without forging the compiler; a type with the
first two is reported, with its own sentence, because it is a different mistake from citing
`string`.

**Required named arguments are present.** `Role` on `[Contract]`, `Scope` on `[DesignDecision]`.
Neither is a constructor parameter — a `Type` is the only argument the attribute's identity needs —
so the compiler treats both as optional and this rule is what makes them required. A `Role` that is
present but empty or whitespace is reported as the same omission: `Role` is the label the report
tool prints next to the contract.

**A `[DomainModel]` prefix is a namespace of the current assembly.** Read from the assembly's own
namespace tree, not the compilation's, so declaring a referenced package's namespace to be this
assembly's domain model is reported rather than silently accepted.

One attribute produces at most one finding. A citation that names nothing real is wrong for that
reason, and fixing it is what brings a missing `Role` into view.

A citation of a decision that does not exist at all — a misspelled key, a set that was never filed —
is `CS0234` or `CS0426` on the same token and is left to the compiler. Two diagnostics about one
misspelling teach a reader to skim one of them.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `dotnet_diagnostic.DD0007.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |

Nothing else. The rule runs wherever one of the four attributes is applied; in a project that never
applies one, it never reports.

## False-positive story

Tier 1 and decidable: every input is a symbol in the compilation being analysed.

The edge the rule cannot decide is forgery, and it sits a long way out. Getting a hand-written type
past this rule means giving a file on disk the synthetic path Roslyn reserves for generator output,
which is forging a compiler input rather than forging a file. An `<auto-generated/>` header or a
marker attribute would have put that edge inside reach of anybody who can type; this does not.

The case that looks like a false positive and is not: citing a decision type that reached the
compilation through metadata rather than being generated into it. The emitted types are `internal`,
so that only happens across an `InternalsVisibleTo` grant, which is DD0002's finding as well as this
one's.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0007
```

No fix is registered, and there is nothing a fix could honestly do. A citation that names no filed
decision cannot be repaired by editing the citation: the decision has to exist first, in the ledger,
and be exported. A code action that inserted a plausible-looking decision type would be writing a
ledger entry from inside an editor, which is the one thing this whole design is arranged to prevent.

A missing `Role` or `Scope` is a one-word edit made where the reader can see what they are asserting.

## Violating example

```csharp
namespace Consumer
{
    [Contract(typeof(string), Role = "store read side")]
    public interface IQuadSource { }
}
```

```text
DD0007: [Contract] cites 'string', which is not a decision type.
Decide: drop the [Contract] attribute, or cite a decision under DecisionDriven.Ledger.* that the generator emitted | file the decision in the ledger, export it, and cite the type the generator emits for it.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
namespace Consumer
{
    [Contract(typeof(DecisionDriven.Ledger.DddAnalyzers.DecisionsAsTypes.AttributesTakeOneDecisionType),
        Role = "store read side")]
    public interface IQuadSource { }
}
```

The type exists because the decision does: the generator emitted it from the ledger export, and
`find all references` on it lists every piece of code that depends on that decision.

A hand-written copy of that type does not pass, even one that copies the `[GeneratedCode]` attribute
off the generated file, because it is in a file rather than in generator output.
