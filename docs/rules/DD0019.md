# DD0019: Model types are immutable

|  |  |
| --- | --- |
| **Id** | `DD0019` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `ImmutableModel.DomainModelImmutable`, `ImmutableModel.MemoizedFieldsAreVerified` |
| **Introduced in** | 0.1.0-preview.1 |

## Principle

A snapshot is only a snapshot if the caller cannot write to it. A value handed out by a pinned read
that the receiver can change was never isolated from anything.

## What the rule checks

Public types in `[DomainModel]` namespaces. Six findings:

- **A settable property.** Public or internal. `init` is fine — it is a setter the caller can only
  reach while the value is being made, which is the distinction the rule is drawing.
- **A field that is not `readonly`.**
- **A member typed as a mutable collection.** `List<T>`, `Dictionary<K,V>`, `HashSet<T>`,
  `ICollection<T>`, `IList<T>`, `ISet<T>`, `IDictionary<K,V>`, `Collection<T>`, and **arrays**.
  An array is the one that gets missed: `public readonly T[] Items` is a readonly reference to a
  thoroughly writable thing, and the `readonly` makes it look answered. Expose `ImmutableArray<T>`,
  `IReadOnlyList<T>`, `ReadOnlyMemory<T>`, `ReadOnlySpan<T>`, `FrozenDictionary` or `FrozenSet`.
- **A struct that is not `readonly`.**
- **A method that changes the value it belongs to.** A non-private instance method on a model
  class whose body writes one of the class's own instance fields or properties (`count++`,
  `this.count = 0`, `ref count`), or invokes a member of a field whose type is mutable by DD0004's
  test (`items.Add(item)`, `counts[key] = value`). The members' shapes can all be private and
  readonly and the type still be as mutable as a type can be:

  ```csharp
  public sealed class Dataset
  {
      private readonly HashSet<Quad> quads = new();
      public bool Add(Quad quad) => quads.Add(quad);   // DD0019
  }
  ```

  A call to a private method of the same class is followed **one level**: `Add` calling a private
  `Insert` that does the adding is reported on `Add`. Deeper than that is out of scope
  (`ImmutableModel.DomainModelImmutable` says so), and so is a property accessor. Writes in a
  constructor are how a value is made; an object initializer on a new instance,
  `new Dataset { Count = n }`, writes to the new value, not this one. Calling a delegate held in a
  field, or `object`'s own members on one, changes nothing and is not reported.

  **A read is not a mutation.** A class may hold a mutable collection privately, fill it in its
  constructor and only read it afterwards. A call on the held field is a read, and is not reported,
  when either:

  - the method implements a member of `IReadOnlyCollection<T>`, `IReadOnlyList<T>`,
    `IReadOnlyDictionary<K,V>` or `IReadOnlySet<T>` that the field's type implements. It is
    matched through the interface map, not by name, so `HashSet<T>.Contains` and
    `Dictionary<K,V>.TryGetValue` are reads because they implement `IReadOnlySet<T>.Contains` and
    `IReadOnlyDictionary<K,V>.TryGetValue`;
  - or it is one of the reads those interfaces leave out, declared by a type in `System.Collections`,
    `System.Collections.Generic` or `System.Collections.ObjectModel`: `Contains` on a field typed
    `HashSet<T>` or `ISet<T>`, `ContainsKey`, `ContainsValue`, `IndexOf`, `GetEnumerator`,
    `TryGetValue`.

  `Count`, an indexer get and `foreach` are property reads or enumeration, not calls the rule
  looks at. Everything else on the field is still a write: `Add`, `Remove`, `Clear`, `TryAdd`, an
  indexer set, `List<T>.Contains` (not on the list), a method group of the field passed as a
  delegate (`more.Where(items.Add)`; `more.Where(items.Contains)` is a read), and any call through
  an interface the rule does not know.

  ```csharp
  public sealed class Scope
  {
      private readonly HashSet<int> named;
      public Scope(IEnumerable<int> named) => this.named = new(named);
      public bool Allows(int g) => named.Contains(g);   // a read: not reported
  }
  ```

- **A `[Memoized]` field that is not one of the two memo forms.** See [Memoized fields](#memoized-fields).

Internal types are not checked: nobody outside holds one to change. Nor is a `public` type nested
inside an internal or private one, for the same reason: the check is effective visibility, the type
and every type containing it public, not the keyword on the declaration.

### Memoized fields

`ImmutableModel.MemoizedFieldsAreVerified`. Some writes after construction are not mutation. A
cached hash, a lazily built immutable view and a per-key cache of a computed answer are written
after the value is handed out. Every reader still sees what the first reader would have computed,
so the observable value never changes. Computing such a value eagerly costs time on every instance,
and it is wrong when the value is expensive and rarely asked for.

Mark the field `[Memoized]`. DD0019 then stops reporting the writes to it and **verifies** the field
against one of two forms. The attribute is a claim the rule checks, not an exemption, so it cites no
decision.

**A value memo.** The field is private and not `readonly`. Its type is a primitive, `string`, an
enum, a type DD0004 judges immutable (`Uri`, `ImmutableArray<T>`, a record with no setters), or
`Nullable<T>` of one. It is written only:

- by `field ??= expr`, or by `if (field == sentinel) field = expr;`, where the sentinel is a
  constant or `default` and the `if` may also test a local copy of the field
  (`var h = field; if (h == 0) { h = expr; field = h; }`);
- in one member of the type and nowhere else: a method, an accessor or a constructor, private ones
  included. A lambda or local function belongs to its member;
- from an `expr` that reads only `readonly` fields, constants, other `[Memoized]` fields, parameters
  and its own locals, reads no property of the type that has a setter, and calls only static
  methods, `object`'s members, members of an immutable type, the held-collection reads below, and
  methods of the type that the body check finds change nothing.

```csharp
public sealed class Name
{
    private readonly string first, last;
    [Memoized] private int hash;
    [Memoized] private string? text;

    public override int GetHashCode()
    {
        if (hash == 0) hash = HashCode.Combine(first, last);
        return hash;
    }

    public override string ToString() => text ??= $"{first} {last}";
}
```

**A per-key memo.** The field is a `readonly`
`System.Collections.Concurrent.ConcurrentDictionary<K, V>` whose `V` is immutable. Only one member
fills it, through `GetOrAdd(key, factory)` or `GetOrAdd(key, factory, arg)`, and the factory is a
`static` lambda or a static method. The key and `arg` are held to the same rule as a value memo's
`expr`. Any member may read the dictionary: `TryGetValue`, `ContainsKey`, `Count`, the indexer get,
`ToArray`, enumeration, and a null test: `is null`, `is not null`, `== null` and `!= null` compare
the reference and give nothing out, so a per-key memo that is only there when configured can be
tested before it is used.

```csharp
[Memoized] private readonly ConcurrentDictionary<Key, bool>? cache;
public bool Allows(Key key) => cache is not null ? cache.GetOrAdd(key, static k => Decide(k)) : Decide(key);
```

A null test beside a hand-out does not excuse it: `cache is not null ? cache : null` returns the
dictionary, and is reported.

```csharp
[Memoized] private readonly ConcurrentDictionary<int, string> labels = new();
public Label For(int id) => new(labels.GetOrAdd(id, static (i, prefix) => prefix + i, this.prefix));
```

**Why a plain collection is refused.** `[Memoized]` on a `Dictionary<K,V>`, `HashSet<T>`,
`List<T>`, any other `System.Collections` collection, or an array is a finding even when every
write to it is guarded. A model value is shared by whoever holds it, and two of them can read it on
two threads at once. Two readers filling a plain collection at the same time is a race: the
collection can be corrupted, not just filled twice. `ConcurrentDictionary.GetOrAdd` is the fill the
framework makes safe, and it makes it safe only for a factory without side effects. That is why the
factory must be static: a lambda that captures `this` or a local would make what is memoised for a
key depend on who asked first. Passing `this` as `arg` is the same capture by another route, and is
reported as one.

Each departure has its own message:

| Departure | Finding |
| --- | --- |
| a plain collection or array | `is [Memoized] and is a plain '…', and a plain collection filled by concurrent readers is a race` |
| any other mutable type | `is [Memoized] and its type, '…', is mutable` |
| a per-key memo of mutable values | `is [Memoized] and the values it holds, '…', are mutable` |
| a dictionary that is not `readonly` | `is a [Memoized] ConcurrentDictionary that is not readonly` |
| a static, non-private, or (for a value memo) `readonly` field | `is [Memoized] and static` · `is not private` · `is [Memoized] and readonly` |
| a second member that fills it | `is [Memoized] and is written by both '…' and '…'` |
| a factory that is not static | `passes '….GetOrAdd' a factory that is not a static lambda or a static method` |
| a computation outside the rule | `computes [Memoized] '…' from …` |
| any other write to a value memo | `writes [Memoized] '…' other than by '… ??= ...' or 'if (… == sentinel) … = ...'` |
| any other call on a per-key memo | `calls '….TryAdd' on the [Memoized] '…', which is neither GetOrAdd with a static factory nor a read` |
| the dictionary itself handed out: returned, stored or passed (a null test is not) | `hands out the [Memoized] '…' itself` |

A field whose shape is refused is reported once, for its shape, and not again for each write to
it. Forms the rule does not accept are reported as "any other write", even when they are correct:
an early return (`if (hash != 0) return hash; hash = …;`), `Interlocked.CompareExchange(ref …)`, and
a write in the constructor. Write the memo in one of the two accepted forms instead.

**The alternatives**, when a value is not one of the two forms:

- **Compute it in the constructor**, into a `readonly` field. This costs time on every instance,
  not only the ones that are asked. It is the right answer when the value is cheap, or nearly always
  needed.
- **Build it in a sealed `*Builder`.** The mutable phase then belongs to the builder, and the value
  it builds holds the result readonly.
- **`Lazy<T>` of an immutable `T`** in a `readonly` field, which DD0004 judges immutable. It
  allocates per instance. A cached hash is the case where that allocation matters.

`[Memoized]` is checked only where DD0019 checks method bodies, which means public model classes.
On any other field the attribute is not read.

### Builders

`ImmutableModel.BuildersAreTheEscapeHatch`. A type whose name ends in `Builder`, in a
`[DomainModel]` namespace, is exempt from all six — assembling a value is what it is for. Two
conditions:

- **It must be `sealed`**, so the mutable thing is one type rather than a hierarchy of them. A
  non-sealed builder is this rule's finding.
- **It may not appear on a `[Contract]` signature**, which is DD0010's finding.

ADR-A11 says DD0010 "already prevents it since a builder is neither model vocabulary nor a
contract". That was not true as written: a builder lives in a `[DomainModel]` namespace by the same
ADR, so DD0010's allow-list accepted it. DD0010 now excludes `*Builder` types from the
`[DomainModel]` allowance, which is the smallest change that makes the decision true. The message
says so:

```text
DD0010: the return type of contract member 'IQuadSource.Read' names 'Consumer.Model.QuadBuilder', which is a builder, which is mutable by design and belongs to the code assembling a value.
```

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |
| `dotnet_diagnostic.DD0019.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |
| `[Memoized]` | on a private field of a model class | absent | The field is verified as a memo instead of each write to it being reported. Absent, every write is a finding as above. |

An assembly with no `[DomainModel]` namespace declared has no model types, so the rule reports
nothing. Declaring the model is what turns it on — the same order the README's quick start asks for.

## False-positive story

Tier 1 and decidable: accessibility, `readonly`, and a list of collection types.

The method-body check classifies calls on a held collection. Reads are what the read-only
interfaces say, plus a short list, and anything it cannot classify is reported. So a read the list
does not name, such as `List<T>.Contains`, `CopyTo` or `Exists`, is still reported. So is a call
through an interface the rule does not know, even one that only reads. That is the intended
direction of error. The remedy is to hold the collection as a read-only or frozen type, or to write
the read as one the rule names. A read taken for a write costs a decision; a write taken for a read
would cost the snapshot.

The case that looks like a false positive and is not: a model type that mutates in place for
performance — a node in a graph being built, a buffer being filled. If it mutates, it is not a
value, and it belongs outside the `[DomainModel]` namespaces or behind a `*Builder`. That is the
consequence ADR-A11 names: stores and datasets that mutate live outside the model, which is
consistent with a log-first design where mutation is a commit.

The genuine edge is a lazily computed cache on a value, such as `private int? hash` filled in
`GetHashCode`. The body check reports the write, because a write is what it sees. `[Memoized]` is
the answer: the rule then verifies the memo instead (see [Memoized fields](#memoized-fields)). The
memo check errs in the same direction as the rest of the rule. A correct memo in a form it does not
accept is reported, and its remedy is to rewrite it in an accepted form.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0019
```

No fix is registered. `set` to `init` looks mechanical and is not: every caller assigning after
construction stops compiling, and deciding whether they should have been is the work. Changing a
`List<T>` to an `ImmutableArray<T>` changes how the type is built.

## Violating example

```csharp
[assembly: DomainModel("Consumer.Model", typeof(CatalogShape.ModelNamespace))]

namespace Consumer.Model
{
    public sealed class Quad
    {
        public int Count { get; set; }
    }
}
```

```text
DD0019: 'Consumer.Model.Quad.Count' has a public setter.
Decide: make it 'init', or take the setter off and set the value in the constructor | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

A memo in a plain collection:

```csharp
namespace Consumer.Model
{
    public sealed class Value
    {
        [Memoized] private readonly Dictionary<int, string> names = new();

        public Label Name(int id)
        {
            if (!names.TryGetValue(id, out string? name)) { name = id.ToString(); names[id] = name; }
            return new Label(name);
        }
    }
}
```

```text
DD0019: 'Consumer.Model.Value.names' is [Memoized] and is a plain 'System.Collections.Generic.Dictionary<int, string>', and a plain collection filled by concurrent readers is a race.
Decide: hold a readonly System.Collections.Concurrent.ConcurrentDictionary<K, V> filled only through GetOrAdd with a static factory, compute it in the constructor, or build it in a sealed *Builder | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
namespace Consumer.Model
{
    public sealed record Quad(int Count)
    {
        public ImmutableArray<Term> Terms { get; init; } = ImmutableArray<Term>.Empty;
    }

    public sealed class QuadBuilder
    {
        public int Count { get; set; }
        public List<Term> Terms { get; } = new();

        public Quad Build() => new Quad(Count) { Terms = Terms.ToImmutableArray() };
    }
}
```

The builder mutates freely and never crosses a contract; what crosses is the `Quad`.

The memo above, in the form DD0019 accepts:

```csharp
[Memoized] private readonly ConcurrentDictionary<int, string> names = new();

public Label Name(int id) => new Label(names.GetOrAdd(id, static i => i.ToString()));
```
