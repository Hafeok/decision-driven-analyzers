# DD0019: Model types are immutable

|  |  |
| --- | --- |
| **Id** | `DD0019` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `ImmutableModel.DomainModelImmutable` |
| **Introduced in** | 0.1.0-preview.1 |

## Principle

A snapshot is only a snapshot if the caller cannot write to it. A value handed out by a pinned read
that the receiver can change was never isolated from anything.

## What the rule checks

Public types in `[DomainModel]` namespaces. Five findings:

- **A settable property.** Public or internal. `init` is fine — it is a setter the caller can only
  reach while the value is being made, which is the distinction the rule is drawing.
- **A field that is not `readonly`.**
- **A member typed as a mutable collection.** `List<T>`, `Dictionary<K,V>`, `HashSet<T>`,
  `ICollection<T>`, `IList<T>`, `ISet<T>`, `IDictionary<K,V>`, `Collection<T>`, and **arrays**.
  An array is the one that gets missed: `public readonly T[] Items` is a readonly reference to a
  thoroughly writable thing, and the `readonly` makes it look answered. Expose `ImmutableArray<T>`,
  `IReadOnlyList<T>`, `ReadOnlyMemory<T>`, `ReadOnlySpan<T>`, `FrozenDictionary` or `FrozenSet`.
- **A struct that is not `readonly`.**
- **A method that changes the value it belongs to.** A non-private instance method on a model
  class whose body writes one of the class's own instance fields or properties (`count++`,
  `this.count = 0`, `ref count`), or invokes a member of a field whose type is mutable by DD0004's
  test (`items.Add(item)`, `counts[key] = value`). The members' shapes can all be private and
  readonly and the type still be as mutable as a type can be:

  ```csharp
  public sealed class Dataset
  {
      private readonly HashSet<Quad> quads = new();
      public bool Add(Quad quad) => quads.Add(quad);   // DD0019
  }
  ```

  A call to a private method of the same class is followed **one level**: `Add` calling a private
  `Insert` that does the adding is reported on `Add`. Deeper than that is out of scope
  (`ImmutableModel.DomainModelImmutable` says so), and so is a property accessor. Writes in a
  constructor are how a value is made; an object initializer on a new instance,
  `new Dataset { Count = n }`, writes to the new value, not this one. Calling a delegate held in a
  field, or `object`'s own members on one, changes nothing and is not reported.

  **A read is not a mutation.** A class may hold a mutable collection privately, fill it in its
  constructor and only read it afterwards. A call on the held field is a read, and is not reported,
  when either:

  - the method implements a member of `IReadOnlyCollection<T>`, `IReadOnlyList<T>`,
    `IReadOnlyDictionary<K,V>` or `IReadOnlySet<T>` that the field's type implements. It is
    matched through the interface map, not by name, so `HashSet<T>.Contains` and
    `Dictionary<K,V>.TryGetValue` are reads because they implement `IReadOnlySet<T>.Contains` and
    `IReadOnlyDictionary<K,V>.TryGetValue`;
  - or it is one of the reads those interfaces leave out, declared by a type in `System.Collections`,
    `System.Collections.Generic` or `System.Collections.ObjectModel`: `Contains` on a field typed
    `HashSet<T>` or `ISet<T>`, `ContainsKey`, `ContainsValue`, `IndexOf`, `GetEnumerator`,
    `TryGetValue`.

  `Count`, an indexer get and `foreach` are property reads or enumeration, not calls the rule
  looks at. Everything else on the field is still a write: `Add`, `Remove`, `Clear`, `TryAdd`, an
  indexer set, `List<T>.Contains` (not on the list), a method group of the field passed as a
  delegate (`more.Where(items.Add)`; `more.Where(items.Contains)` is a read), and any call through
  an interface the rule does not know.

  ```csharp
  public sealed class Scope
  {
      private readonly HashSet<int> named;
      public Scope(IEnumerable<int> named) => this.named = new(named);
      public bool Allows(int g) => named.Contains(g);   // a read: not reported
  }
  ```

Internal types are not checked: nobody outside holds one to change. Nor is a `public` type nested
inside an internal or private one, for the same reason: the check is effective visibility, the type
and every type containing it public, not the keyword on the declaration.

### Builders

`ImmutableModel.BuildersAreTheEscapeHatch`. A type whose name ends in `Builder`, in a
`[DomainModel]` namespace, is exempt from all five — assembling a value is what it is for. Two
conditions:

- **It must be `sealed`**, so the mutable thing is one type rather than a hierarchy of them. A
  non-sealed builder is this rule's finding.
- **It may not appear on a `[Contract]` signature**, which is DD0010's finding.

ADR-A11 says DD0010 "already prevents it since a builder is neither model vocabulary nor a
contract". That was not true as written: a builder lives in a `[DomainModel]` namespace by the same
ADR, so DD0010's allow-list accepted it. DD0010 now excludes `*Builder` types from the
`[DomainModel]` allowance, which is the smallest change that makes the decision true. The message
says so:

```text
DD0010: the return type of contract member 'IQuadSource.Read' names 'Consumer.Model.QuadBuilder', which is a builder, which is mutable by design and belongs to the code assembling a value.
```

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |
| `dotnet_diagnostic.DD0019.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |

An assembly with no `[DomainModel]` namespace declared has no model types, so the rule reports
nothing. Declaring the model is what turns it on — the same order the README's quick start asks for.

## False-positive story

Tier 1 and decidable: accessibility, `readonly`, and a list of collection types.

The method-body check classifies calls on a held collection. Reads are what the read-only
interfaces say, plus a short list, and anything it cannot classify is reported. So a read the list
does not name, such as `List<T>.Contains`, `CopyTo` or `Exists`, is still reported. So is a call
through an interface the rule does not know, even one that only reads. That is the intended
direction of error. The remedy is to hold the collection as a read-only or frozen type, or to write
the read as one the rule names. A read taken for a write costs a decision; a write taken for a read
would cost the snapshot.

The case that looks like a false positive and is not: a model type that mutates in place for
performance — a node in a graph being built, a buffer being filled. If it mutates, it is not a
value, and it belongs outside the `[DomainModel]` namespaces or behind a `*Builder`. That is the
consequence ADR-A11 names: stores and datasets that mutate live outside the model, which is
consistent with a log-first design where mutation is a commit.

The genuine edge is a lazily computed cache field on a value — `private int? hash`. It is `private`,
so the rule does not see it, and that is correct: nobody outside can change it.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0019
```

No fix is registered. `set` to `init` looks mechanical and is not: every caller assigning after
construction stops compiling, and deciding whether they should have been is the work. Changing a
`List<T>` to an `ImmutableArray<T>` changes how the type is built.

## Violating example

```csharp
[assembly: DomainModel("Consumer.Model", typeof(CatalogShape.ModelNamespace))]

namespace Consumer.Model
{
    public sealed class Quad
    {
        public int Count { get; set; }
    }
}
```

```text
DD0019: 'Consumer.Model.Quad.Count' has a public setter.
Decide: make it 'init', or take the setter off and set the value in the constructor | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
namespace Consumer.Model
{
    public sealed record Quad(int Count)
    {
        public ImmutableArray<Term> Terms { get; init; } = ImmutableArray<Term>.Empty;
    }

    public sealed class QuadBuilder
    {
        public int Count { get; set; }
        public List<Term> Terms { get; } = new();

        public Quad Build() => new Quad(Count) { Terms = Terms.ToImmutableArray() };
    }
}
```

The builder mutates freely and never crosses a contract; what crosses is the `Quad`.
