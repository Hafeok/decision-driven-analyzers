# DD0023: Keep the namespaces of a layered project acyclic

|  |  |
| --- | --- |
| **Id** | `DD0023` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `StableDependencyRules.NamespacesAcyclicWithinAssembly` |
| **Introduced in** | 0.1.0-preview.12 |

## Principle

Two namespaces that reference each other are one namespace with two names. DD0001 keeps references
between assemblies pointing one way; inside an assembly the namespaces are the structure, and a cycle
through them is a structure that says nothing about which part depends on which.

## What the rule checks

In a compilation with `ArchLayer` set, the rule builds a graph whose **nodes** are the namespaces of
the types declared in source in that compilation and whose **edges** run from the namespace of the
type whose declaration contains a reference to the namespace of the type referenced, when both are
source types of this compilation and the namespaces differ. At the end of the compilation it finds
the strongly connected components of that graph and reports **every edge inside a non-trivial
component**, once, at the first location that made it (lowest file path, then lowest span). The
message names both namespaces and one shortest path from the target back to the source.

A **reference** is any type symbol the declaration binds:

- base types and interfaces, attribute types, type parameter constraints;
- member signatures: return types, parameter types, property, field and event types, a delegate's
  signature, generic arguments wherever they appear;
- anything bound in a body or an initialiser: object creation, invocation (including a static
  method's class, an extension method's class and a generic call's type arguments), member access,
  `typeof`, `nameof`, `sizeof`, `default`, `is` and `as`, casts, patterns, local declarations, lambda
  and local function signatures, `catch` clauses, arrays and tuples.

Three things the decision says about the graph:

- **A nested type belongs to the namespace of its outermost containing type.** `A.Outer.Inner`
  referring to `B.Y` is an edge from `A`, not from `A.Outer`.
- **Parent and child namespaces are distinct nodes.** `Sample.Core` and `Sample.Core.Inner` referring
  to each other is a cycle.
- **A `using` directive alone is not a reference.** Only what the code binds counts.

Generated code contributes no edges (`RuleTiers.GeneratedCodeIsExempt`): neither a generated file
nor the generated half of a partial type. A reference from source to a generated type is an edge to
that type's namespace, which never refers back.

```csharp
namespace Sample.Core.Ping { public sealed class Ping { public Pong.Pong? Other; } }
namespace Sample.Core.Pong { public sealed class Pong { public Ping.Ping? Other; } }
// DD0023 at Ping.Other: 'Sample.Core.Ping' refers to 'Sample.Core.Pong' ... Sample.Core.Pong -> Sample.Core.Ping
// DD0023 at Pong.Other: 'Sample.Core.Pong' refers to 'Sample.Core.Ping' ... Sample.Core.Ping -> Sample.Core.Pong
```

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |
| `dotnet_diagnostic.DD0023.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |

With no `ArchLayer` the rule does not run: a project that has not declared a layer has not opted into
the layering this rule protects. With one, it runs in every project, like DD0020, and it has **no
switch of its own**: an `.editorconfig` switch on a tier-1 rule is a suppression path DD0008 cannot
see (ADR-A17). A consumer adopts it by upgrading the package when its namespaces are acyclic; the
release notes for the version that introduced it say so.

## False-positive story

Tier 1 and decidable: the edges are what the compiler bound, and a cycle in a finite graph is a
fact. The edge cases are rulings, not guesses:

- **Every edge of a cycle is reported**, not one per cycle. A three-namespace cycle is three
  findings; fixing one of them breaks the cycle and clears all three. The message's way back is one
  shortest path, so a reader knows which other edge to look at.
- **A reference that is on no cycle is never reported**, however many namespaces a project has. A
  deep tree, a diamond, a chain: all silent. `NamesAndNamespaces.NamespaceDepthNotRequired` says the
  rule asks for no structure, only that the structure present is acyclic.
- **A reference through a nested type** counts for the outer type's namespace, which is where the
  nested type is declared.

The honest exception is a migration in progress: a cycle being unpicked over several changes, where
the type that closes it has not moved yet. That is
`[DesignDecision(..., Scope = ExceptionScope.Migration)]` on that type, citing the decision that says
the move is under way; it removes that type's outgoing edges and nothing else.

Suppressing the diagnostic is not an answer (that is DD0008).

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0023
```

No fix is registered. Breaking a cycle means deciding which namespace the type that closes it
belongs in, or that the two namespaces are one; neither is a transformation of one file. The
documented-exception path is `[DesignDecision]` on a type, and a declaration-level placeholder would
sit on the type the diagnostic's location happens to be in rather than on the one that should move,
so the shared placeholder fix is not offered either.

## Violating example

```csharp
// ArchLayer=1
namespace Sample.Core.Ping
{
    public sealed class Ping { public global::Sample.Core.Pong.Pong? Pong; }
}

namespace Sample.Core.Pong
{
    public sealed class Pong { public global::Sample.Core.Ping.Ping? Ping; }
}
```

```text
DD0023: namespace 'Sample.Core.Ping' refers to 'Sample.Core.Pong' here, and the reference comes back: Sample.Core.Pong -> Sample.Core.Ping.
Decide: move the type that closes the cycle into the namespace that uses it, or merge the two namespaces, which is what the cycle says they are | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

The second finding, at `Pong.Ping`, reads the same way round.

## Conforming example

```csharp
// ArchLayer=1
namespace Sample.Core.Ping
{
    public sealed class Ping { public global::Sample.Core.Pong.Pong? Pong; }
}

namespace Sample.Core.Pong
{
    public sealed class Pong { }   // what Pong needed from Ping now lives here, or Pong never needed it
}
```

One direction only. A single-namespace assembly conforms too: with one node there is no edge.
