# DD0010: Keep contract signatures inside the agreed vocabulary

|  |  |
| --- | --- |
| **Id** | `DD0010` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `Contracts.ContractVocabularyAllowList` |
| **Introduced in** | unreleased |

## Principle

Implementing a contract means taking on every type in its signatures, and calling one means the
same. Nobody agreed to those separately by agreeing to the contract.

## What the rule checks

Every type named on a `[Contract]` type's surface — return types, parameters, property and event
types, and the generic arguments and array elements inside all of them — comes from one of four
places:

- **the BCL**, matched by assembly: the core library by identity, and `System`, `System.*`,
  `mscorlib` and `netstandard` by name. There is no symbol meaning "the framework", and which
  assembly a framework type lands in is a detail of how the framework was factored rather than
  something a consumer chose.
- **a `[DomainModel]` namespace of the current assembly**, from the assembly-level
  `[DomainModel(prefix, decision)]` attributes. A prefix matches its own namespace and everything
  under it.
- **an assembly named in `ArchContractTypeAssemblies`**.
- **a type that is itself `[Contract]`-marked**, wherever it lives. A declared contract may name
  another declared contract.

A generic argument is checked like anything else: `IReadOnlyList<Undecided>` exposes the undecided
type exactly as plainly as returning it would. A type parameter is not checked — it is whatever the
caller supplies, and the caller's own contract is where that gets decided.

One position reports once, however many times the type is named in it. Two positions report twice,
because there are two places to edit.

Only `[Contract]`-marked types are examined. An unmarked public interface is DD0009's finding, and
reporting its signature as well would report one omission twice.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `ArchContractTypeAssemblies` | MSBuild property | none | Assembly simple names, separated by `;` (commas are accepted too). Their types may appear on contract signatures. |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |
| `ArchCompositionRoot` | MSBuild property | `false` | `true` excludes the project. |
| `dotnet_diagnostic.DD0010.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |

With `ArchContractTypeAssemblies` unset, the allow-list is the other three sources. That is a
working configuration, not a broken one: a package whose contracts speak only BCL types and its own
domain model needs nothing here.

## False-positive story

Tier 1 and decidable: every input is a symbol in the compilation.

The rule is strict about the current assembly on purpose. A public type of this assembly that is not
in a `[DomainModel]` namespace and is not itself a contract is reported, because "it is ours" is not
one of the four answers — the point of `[DomainModel]` is that somebody drew the line between the
model and the internals.

Adding an assembly to `ArchContractTypeAssemblies` is the escape hatch, and it is deliberately a
visible project-file change: every consumer of the contract now depends on that assembly, so the
decision belongs where somebody reviews it.

An assembly that has declared no `[DomainModel]` namespace at all will see every contract signature
reported at once. That is the rule asking, once per signature, a question the assembly has not
answered: which of its namespaces are the model. Declaring `[DomainModel]` before adding the first
`[Contract]` is the order that avoids it, and the README's quick start says so first.

This rule is the one whose message does not end in `[DesignDecision]`. Both of its answers are
configuration rather than a citation — say which namespaces are the model, or say which assemblies a
contract may name — so the message names the actual namespace and the actual assembly instead.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0010
```

No fix is registered, and the answers are why. Changing the type is a design change; declaring a
namespace `[DomainModel]` or adding an assembly to `ArchContractTypeAssemblies` is an edit outside
the file with a decision behind it; marking the offending type `[Contract]` needs a decision key.
None of them is a thing a code action can choose between without guessing which dependency the
author meant to take on.

## Violating example

```csharp
// in a project with ArchContractTypeAssemblies=Sample.Layer0
namespace Consumer
{
    [Contract(typeof(CatalogShape.ProductLookupContract), Role = "catalog read side")]
    public interface IProductLookup
    {
        Sample.Layer1.Extras.Scratch Find(ProductId id);
    }
}
```

```text
DD0010: the return type of contract member 'IProductLookup.Find' names 'Sample.Layer1.Extras.Scratch', which comes from 'Sample.Layer1.Extras', which is not in ArchContractTypeAssemblies.
Decide: use a type this contract may already name, or take what it needs into this assembly's [DomainModel] namespaces | add 'Sample.Layer1.Extras' to ArchContractTypeAssemblies, in a decision that says why every consumer of this contract now depends on 'Sample.Layer1.Extras'.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

For a type of this assembly the two paths are the other question — what this assembly's model is —
and each names the thing it is about:

```text
DD0010: the return type of contract member 'IProductLookup.Find' names 'Consumer.Scratch.Thing', which is declared in this assembly outside any [DomainModel] namespace.
Decide: declare the namespace as model with [assembly: DomainModel("Consumer.Scratch", typeof(<Set>.<Key>))], or move the type into a namespace already declared | mark 'Consumer.Scratch.Thing' itself [Contract(typeof(<Set>.<Key>), Role = "...")].
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
[assembly: DomainModel("Consumer.Model", typeof(CatalogShape.ModelNamespace))]

namespace Consumer
{
    [Contract(typeof(CatalogShape.ProductLookupContract), Role = "catalog read side")]
    public interface IProductLookup
    {
        Consumer.Model.Product? Find(Consumer.Model.ProductId id);
    }
}
```

The types are the assembly's own domain model, declared as such, so every consumer of the contract
is depending on something somebody decided to expose.
