# DD0020: Do not use `dynamic` in a layered project

|  |  |
| --- | --- |
| **Id** | `DD0020` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `StableDependencyRules.NoDynamicInLayeredProjects` |
| **Introduced in** | unreleased |

## Principle

A dynamically bound call reaches whatever the runtime object happens to be. DD0001 stops a lower
layer referencing a higher one, and DD0011 stops a contract taking `object` where it means a
collaborator; `dynamic` walks round both, because a call the compiler does not bind needs no
reference to the type it lands on.

## What the rule checks

In a project with `ArchLayer` set, two things, each reported once per syntax node:

- **`dynamic` as a type**, wherever it is written: a local, a field, a property, a parameter, a
  return type, a cast, a generic argument (`List<dynamic>`).
- **A dynamically bound operation**: an invocation, member access, indexer access or object
  creation the compiler leaves to the runtime binder. Only the outermost one of an expression is
  reported, so `Source().Next.Handle(1)` is one finding, not three. A value declared `dynamic`
  somewhere else, a member of a referenced assembly included, is reported where it is used.

```csharp
public static void Forward(object handler, string message)
{
    dynamic target = handler;       // DD0020: 'dynamic' as a type
    target.Handle(message);         // DD0020: bound at run time
}
```

`StableDependencyRules.CallbackLoopholeNeedsNoRule` used to say banned symbols closed this. They
cannot: the compiler lowers a dynamic operation to `Microsoft.CSharp.RuntimeBinder` call sites the
source never names, and a banned-symbol analyzer sees only the symbols the source names. Banning
`N:Microsoft.CSharp.RuntimeBinder` reports an explicit `Binder.InvokeMember(...)` and nothing else.
The decision is amended to name this rule instead.

An identifier that is merely spelled `dynamic`, such as a local named `dynamic` of type `string`, is
not reported: the rule asks the compiler what the name binds to.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |
| `dotnet_diagnostic.DD0020.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |

With no `ArchLayer` the rule does not run: a project that has not declared a layer has not opted into
the layering this rule protects. With one, it runs in every project, a composition root and a test
assembly that sets a layer included: the decision names no exemption.

## False-positive story

Tier 1 and decidable: `TypeKind.Dynamic` on a written type, and the compiler's dynamic operations
in a body. Neither is a guess.

The honest uses are COM interop and some JSON or scripting hosts, where `dynamic` is how the API is
meant to be used. Those are not false positives: they are the exception, and the answer is
`[DesignDecision(..., Scope = ExceptionScope.Interop)]` on the member or on the type that contains
it, citing the decision that says so. Such code normally sits in an adapter; keeping it there keeps
the citation in one place.

Suppressing the diagnostic is not an answer (that is DD0008).

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0020
```

No fix is registered. Replacing `dynamic` means deciding what contract the value is used through,
which is the work the rule is asking for.

## Violating example

```csharp
// ArchLayer=1
namespace Sample.Core;

public static class Relay
{
    public static dynamic Wrap(object o) => o;
}
```

```text
DD0020: 'Relay.Wrap' uses 'dynamic' as a type, so what a value of it can do is decided at run time.
Decide: type the value as the contract it is used through, and test for that with 'is', so the compiler binds the call | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
// ArchLayer=1
namespace Sample.Core;

public interface IHandler { void Handle(string message); }

public static class Relay
{
    public static void Forward(object handler, string message)
    {
        if (handler is IHandler target)
        {
            target.Handle(message);
        }
    }
}
```
