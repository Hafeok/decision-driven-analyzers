# DD0012: Do not claim a member you do not honour

|  |  |
| --- | --- |
| **Id** | `DD0012` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `Contracts.NoNotSupportedFromContractMember` |
| **Introduced in** | unreleased |

## Principle

A member that throws rather than works is an interface sized for somebody else's client. The promise
is in the type, the refusal is in the body, and every caller now has to know which implementations
mean it — which is the knowledge the interface existed to remove.

## What the rule checks

`throw new NotSupportedException(...)`, as a statement or an expression, anywhere inside a member
that either overrides a member or implements an interface member, implicitly or explicitly.

Anywhere, not only as the member's single statement. A refusal behind an `if` is the same claim with
a condition on it, and it is the harder one to find by reading.

A property or event accessor is reported as the property or event. The claim being broken is the
property's, and naming its getter would name a member nobody wrote.

A method that implements nothing and overrides nothing is not reported: no contract said otherwise,
and a method that throws is a method that throws.

`NotImplementedException` is not this rule's finding. That is DD0018.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |
| `ArchCompositionRoot` | MSBuild property | `false` | `true` excludes the project. |
| `dotnet_diagnostic.DD0012.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |

`*.Tests` assemblies are excluded: a stub that throws from the members a test does not exercise is
the normal shape of a test double, and the interface it implements is not this assembly's promise.

## False-positive story

Tier 1 and decidable: the thrown type and whether the containing member implements or overrides
something, both in the compilation.

The case that looks like a false positive and is not: implementing a framework interface that is
explicitly designed to be partially supported — the read-only `IList<T>` shape, where
`NotSupportedException` is the documented answer. The rule reports it, and that is correct, because
the type is still claiming members it does not honour. What has changed is that the decision was
made by whoever designed the interface rather than by whoever implemented it, and that is exactly
what `[DesignDecision(..., Scope = ExceptionScope.Compatibility)]` on the member is for.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0012
```

No fix is registered. Splitting an interface is a change to every implementer and every caller, and
removing the member changes the type's surface; neither is something a code action should do while
somebody is reading a lightbulb menu.

## Violating example

```csharp
namespace Consumer
{
    public sealed class EmptySource : IProductLookup
    {
        public Product? Find(ProductId id) => throw new NotSupportedException();
    }
}
```

```text
DD0012: 'Consumer.EmptySource.Find' throws NotSupportedException, and implements 'Consumer.IProductLookup.Find'.
Decide: split the interface so that this type only claims what it honours, or stop implementing the member | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
namespace Consumer
{
    public sealed class EmptySource : IProductCount
    {
        public int Count => 0;
    }
}
```

The interface was two promises, and this type only ever made one of them. Splitting it is the design
change; the alternative is that `EmptySource` stops claiming to be a lookup.
