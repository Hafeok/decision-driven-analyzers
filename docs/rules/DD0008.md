# DD0008: Do not suppress a DecisionDriven rule

|  |  |
| --- | --- |
| **Id** | `DD0008` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error, and not configurable |
| **Motivating decision** | `DecisionsAsTypes.NoPragmaOrSuppressMessage` |
| **Introduced in** | 0.1.0-preview.1 (with a defect fixed since; see the [changelog](../../CHANGELOG.md)) |

## Principle

Every other rule here can be answered two ways: change the design, or cite a decision that says the
violation is intended. A suppression is a third way, and the only one that leaves the code exactly
as it was.

## What the rule checks

Three ways of silencing a rule, all of them errors:

**`#pragma warning disable`**, and `restore` with it. A restore is half of a pair and the pair is the
suppression; reporting only the disable would leave `restore` reading as an undo to anyone skimming
a diff.

A pragma inside an inactive `#if` branch is not reported. It suppresses nothing in that
compilation; the build that defines the symbol activates it and reports it there. A suppression
hidden behind a define no build ever sets is therefore not found - the answer to that is building
every configuration you ship, which the rule cannot do for you.

**`[SuppressMessage]`**, wherever it is applied, read from its `checkId` argument — the id before the
colon.

**An `.editorconfig` severity below the rule's declared tier.** `dotnet_diagnostic.DD0001.severity =
warning` is a suppression spread across a repository instead of a line. Raising a severity is not
reported; `default` is not reported. The comparison is against the severity the rule's tier declares
(`RuleTiers.ThreeTiers`), so a tier-2 rule set to `warning` is at its tier, not below it.

An id counts when it belongs to one of the families this package ships (`RuleTiers.IdFamilies`:
`DD`, `DDBUILD`, `DDGEN`) followed by digits. `CS0168` and `IDE0044` are not this rule's business.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `dd_rule_id_prefixes` | `.editorconfig` | `DD`, `DDBUILD`, `DDGEN` | Extra id prefixes, comma separated, for a product package's own rules. Added to the built-in families rather than replacing them. |

`TwoPackages.RuleIdPrefixDD` leaves a product's prefix to the product, and this package cannot know
it. `TwoPackages.ConfigurationViaMsBuildProperties` allows `.editorconfig` options, which is where
this one is read from:

```ini
[*.cs]
dd_rule_id_prefixes = ACME, CONTOSO
```

A product analyzer package sets this for its own consumers by shipping a `.globalconfig` in its
`build/` folder, the same way this package ships its `.props` and `.targets`:

```ini
is_global = true

dd_rule_id_prefixes = ACME
```

so nobody consuming that package has to know the option exists, or that DD0008 is the reason their
`#pragma warning disable ACME0001` stopped working.

**DD0008 itself is not configurable.** Its descriptor carries `NotConfigurable`, so no pragma, no
`[SuppressMessage]` and no `.editorconfig` entry reaches it — including an entry naming DD0008,
which is why such an entry is not reported either: it changes nothing, and sending somebody to
delete it would send them after the one harmless line. A rule against suppression that could be
suppressed would be a comment.

## False-positive story

Tier 1 and decidable: it reads directives, attribute arguments and configuration entries, all of
them literally present.

There is no exception path, and that is the rule rather than a gap. `[DesignDecision]` is how a
consumer accepts a violation of some *other* rule; there is nothing for it to mean here, because the
thing being accepted would be the act of not answering. The two honest answers to a DD0008 finding
are:

- delete the suppression and answer the rule it was hiding — change the design, or mark the symbol
  `[DesignDecision]` citing an accepted decision; or
- change the rule, by superseding the decision that set its tier, here in
  `DecisionDriven.Analyzers`. A tier is a decision in this repository, not a consumer setting.

Generated code is analysed and reported, unlike for every other rule: a file named `*.g.cs` or
starting with `// <auto-generated/>` is where a suppression would otherwise go unseen. A generator
that emits a pragma disabling a DD rule has silenced it just as thoroughly as a hand-written one,
and the fix is that the generator stops emitting it. (Before the release after `0.1.0-preview.2`,
DD0008 analysed generated code but reported nothing found there.)

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0008
```

No fix is registered. Deleting the suppression is trivial, and doing it automatically would leave
whatever the suppression was hiding to surface on the next build with nobody having decided
anything — the suppression moved, not answered.

Delete it by hand, look at what the rule then reports, and answer that.

## Violating example

```csharp
#pragma warning disable DD0004
namespace Consumer
{
    public sealed class Thing { }
}
```

```text
DD0008: #pragma warning disable silences DD0004, a DD rule.
Decide: delete the pragma and answer DD0004 where it reports: change the design, or mark the symbol [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing an accepted decision | change the rule itself, by superseding the decision that set its tier in DecisionDriven.Analyzers.
Do not reach for a suppression to get to green; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
namespace Consumer
{
    public sealed class Thing
    {
        [DesignDecision(typeof(DecisionDriven.Ledger.DddAnalyzers.StaticState.PoolsExemptByDesignDecision),
            Scope = ExceptionScope.Pool)]
        private static readonly System.Buffers.ArrayPool<byte> Pool = System.Buffers.ArrayPool<byte>.Shared;
    }
}
```

The rule is still reporting; the violation is accepted, by a decision, with a citation left behind
that the report tool can find.
