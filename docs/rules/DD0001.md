# DD0001: Do not reference a family assembly that is not strictly below you

|  |  |
| --- | --- |
| **Id** | `DD0001` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `StableDependencyRules.LayerReferenceStrictlyDownward` |
| **Introduced in** | unreleased |

## Principle

Dependencies within one family point in one direction. A graph where every edge goes strictly
downward cannot contain a cycle, and you can read any layer without reading the ones above it.

## What the rule checks

For a project with `ArchFamily=F` and `ArchLayer=n`, every referenced assembly whose name begins
`F.` must declare `ArchLayer` **strictly less than** `n`.

The referenced layer is read from an assembly-level `[ArchLayer(n)]` attribute in the referenced
assembly's **metadata** — not from an MSBuild property, which only the project being compiled can
see. That is `StableDependencyRules.LayerDeclaredInAssemblyMetadata`, and it is what makes the rule
work across a package reference exactly as it does across a project reference.

Three ways to fail, one way to pass:

| Referenced `F.*` assembly | Result |
| --- | --- |
| declares a lower layer | conforms |
| declares the same layer | reported |
| declares a higher layer | reported |
| declares no layer | reported |

The attribute is matched by full name, not by symbol identity: every assembly has its own `internal`
copy (`DecisionsAsTypes.AttributesAreSourceGenerated`), so the attribute class on a referenced
assembly is never the same symbol as the one in the compilation doing the checking.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `ArchFamily` | MSBuild property | unset | The family this project is in. Unset means the rule does not run. |
| `ArchLayer` | MSBuild property | unset | This project's layer. Unset means the rule does not run. |

With either unset the rule is **silent**. That is deliberate: unset is a real state meaning the
project has not been placed, and it is not layer 0. Reporting here would make adopting the package a
build break for every project nobody had got to yet.

An assembly whose name ends `.Tests` is not checked, per the decision: a test reaches across layers
on purpose. It still counts as a reference when something else references it.

## False-positive story

Tier 1 and decidable: the rule compares two integers that are both in metadata. The two places it
can look wrong are both configuration rather than the rule:

- **A family assembly nobody placed.** Reported as "declares no layer", which reads like a
  complaint about the reference and is really a complaint about the reference's project. Set
  `ArchLayer` there.
- **Two products sharing a name prefix.** The family match requires the dot: family `Sample`
  matches `Sample.Layer0` and does not match `Samples.Other`. If two unrelated products genuinely
  share a dotted prefix, they are one family as far as this rule is concerned, and the fix is to
  name one of them differently.

Suppressing the diagnostic is not an answer (that is DD0008). If the reference is genuinely
intended, the exception path is `[assembly: DesignDecision(...)]` citing the decision that says so.

## Violating example

`Sample.Layer1` (`ArchFamily=Sample`, `ArchLayer=1`) referencing `Sample.Sibling`, which declares
layer 1:

```csharp
// Sample.Layer1.csproj references Sample.Sibling
internal sealed class Consumer { }
```

```text
DD0001: 'Sample.Layer1' is at layer 1 and references 'Sample.Sibling', which is at layer 1.
Decide: move what 'Sample.Layer1' needs down to a layer below 1, or invert the dependency so 'Sample.Sibling' does not have to be referenced from layer 1 | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

`Sample.Layer1` referencing `Sample.Layer0`, which declares layer 0:

```xml
<PropertyGroup>
  <ArchFamily>Sample</ArchFamily>
  <ArchLayer>1</ArchLayer>
</PropertyGroup>

<ItemGroup>
  <ProjectReference Include="../Sample.Layer0/Sample.Layer0.csproj" />
</ItemGroup>
```

The reference points down, so it is silent. `samples/Consumer/` is this shape, and CI builds it on
every change (`RuleTiers.SamplesJobIsTheFalsePositiveCheck`).
