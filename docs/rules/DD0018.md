# DD0018: No placeholder bodies in code that ships

|  |  |
| --- | --- |
| **Id** | `DD0018` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `Hierarchies.NoNotImplementedException` |
| **Introduced in** | unreleased |

## Principle

`NotImplementedException` is the one exception type that says nothing about the domain and
everything about the schedule. It compiles, it passes review, and the only way to find one later is
to grep for it.

## What the rule checks

`new NotImplementedException(...)` anywhere in a non-test assembly — in a method, a property or
event accessor, a lambda, a local function, a field initialiser.

The **construction** is reported, not the throw, so `throw new NotImplementedException()` is one
finding rather than two. A `NotImplementedException` that is constructed and not thrown is still a
placeholder and is still found.

An accessor is reported as its property: the getter has no name a reader would recognise. A lambda
is reported as the member containing it, which is where somebody will go looking.

`*.Tests` assemblies are excluded. A test that asserts a member throws has to be able to write the
throw.

`NotSupportedException` is not this rule's finding — see below.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `dotnet_diagnostic.DD0018.severity` | `.editorconfig` | `error` (tier 1) | Downgrading it below `error` is DD0008. |

Nothing else, and in particular not `ArchLayer`. The contract rules wait for a project to declare a
layer because they are about the surface a layered project exposes; this one is about the code, and
a placeholder is a placeholder in whichever project it sits. A host, or a project that has not
adopted the layering rules at all, is where one is most likely to survive, so the rule runs in every
project that references the package except `*.Tests`.

## False-positive story

Tier 1 and decidable: one type, matched by symbol.

**There is no `[DesignDecision]` path, and that is the rule rather than a gap.** Every other rule
here can be answered by citing a decision. A citation on a `NotImplementedException` would make the
placeholder permanent *and* still invisible — the one thing worse than a placeholder is a placeholder
with paperwork.

A deliberate stub has a shape, and it is a different one:

```csharp
[DesignDecision(typeof(ReleasePlan.StreamingNotInV1), Scope = ExceptionScope.Migration)]
public Stream OpenStream() => throw new NotSupportedException("Streaming lands in v2; see the decision.");
```

`NotSupportedException` says something true about the domain — this operation is not supported —
rather than something true about a sprint. DD0012 then reports it, the citation names the decision,
and the report tool lists it: the stub is in the index instead of in a grep. That is the second path
in this rule's message, and it is the reason the message does not end in `[DesignDecision]` like the
others.

The case that looks like a false positive and is not: a generated file, or an interface
implementation scaffolded by an IDE. Both are exactly what the rule is for.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0018
```

No fix is registered. A fix that swapped the exception type would turn the finding into a DD0012
finding with no decision behind it, which is the paperwork answer this rule exists to refuse.

## Violating example

```csharp
namespace Consumer
{
    public sealed class Thing
    {
        public int Read() => throw new NotImplementedException();
    }
}
```

```text
DD0018: 'Consumer.Thing.Read' has a NotImplementedException in it.
Decide: write the member, or take it off the type until there is something to write | if it is a deliberate stub, make it a NotSupportedException marked [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)], which DD0012 tracks and the report tool lists.
Do not leave it as it is; a placeholder nobody can find is a placeholder that ships.
```

## Conforming example

```csharp
namespace Consumer
{
    public sealed class Thing
    {
        public int Read() => this.count;
    }
}
```

Or the member is not on the type yet. A type with three members that work is a better type than one
with four where the fourth throws.
