# DD0013: Keep naked primitives off model and contract surfaces

|  |  |
| --- | --- |
| **Id** | `DD0013` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `PrimitiveFreeSurfaces.NoNakedPrimitivesOnModelAndContract` |
| **Introduced in** | 0.1.0-preview.1 |

## Principle

`Read(long position, ulong graphId)` is two arguments the compiler will let a caller swap, standing
for two things that are not the same. The wrapper type is where the difference gets written down.

## What the rule checks

Two surfaces: every member of a `[Contract]` type, and every externally visible member of a type in
a `[DomainModel]` namespace. Parameters, return types, property and event types.

**Banned** by default: `string`, `char`, the integer and floating-point types including `nint`,
`nuint` and `Half`, `Guid`, `DateTime`, `DateTimeOffset`, `TimeSpan`, `DateOnly`, `TimeOnly`, and
`object`.

**Looked through**, so the primitive inside is found: arrays, `Task<T>`, `ValueTask<T>`,
`Nullable<T>`, `IEnumerable<T>`, `IReadOnlyList<T>`, `IReadOnlyCollection<T>`, `IList<T>`,
`ICollection<T>`. `Task<string>` is a string with waiting attached.

**Not looked through, whatever they hold**: `ReadOnlySpan<T>`, `Span<T>`, `Memory<T>`,
`ReadOnlyMemory<T>`. A span is a window onto memory rather than a surface saying "a number", and it
is what the parse boundary and the hot paths are made of.

**Never banned**: `bool` (a `bool` parameter is DD0016's warning, not this rule's error), enums,
generic type parameters, `CancellationToken` and every other type not on the list.

### The boundary

`PrimitiveFreeSurfaces.BoundaryMembersExempt`. Primitives have to enter somewhere, and a rule
without an exemption would ask for a model nobody could build. Exempt:

- members named `Parse`, `TryParse`, `Format`, `TryFormat`;
- constructors, and static members returning the type they live on — the factory, matched by shape
  rather than by the word `Create`, because `Of`, `From` and the type's own name are all in use and
  none is more of a factory than the others;
- members implementing `IParsable<T>`, `ISpanParsable<T>`, `IUtf8SpanParsable<T>`, `IFormattable`,
  `ISpanFormattable` or `IUtf8SpanFormattable`;
- anything marked `[HotPath]` or `[DesignDecision]`, member or type.

One more, `PrimitiveFreeSurfaces.WrapperExposesItsOwnPrimitive`: **on a type that wraps a single
banned primitive, that primitive is exempt.** `Position` wraps a `long`, so `Position(long)` and
`Position.Value` are fine, and `Position.Other` returning a `Guid` is not. Without it, `.Value` is
an error and the wrapper the rule asked for cannot be read back.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `dd_banned_primitive_types_add` | `.editorconfig` | empty | **Adds** to the list above; it can never remove from it. Names are matched by keyword (`long`) or by full name (`System.Int64`); both spellings work. |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |
| `ArchContractTypeAssemblies`, `ArchCompositionRoot` | MSBuild property | | As for the other contract rules. |

`PrimitiveFreeSurfaces.BannedPrimitiveListIsAdditiveOnly`. The option adds and cannot remove, and
the name says so. A list a consumer could shorten would be a suppression path around this rule with
no citation anywhere — `dd_banned_primitive_types = Guid` would silently unban `string` and `long`
across a whole repository, which is precisely what DD0008 exists to prevent. Taking a type off the
list is a superseding decision here, not a consumer setting.

An assembly that has declared no `[DomainModel]` namespace gets this rule on its `[Contract]` types
only. Declaring the model is what brings model types into scope.

## False-positive story

Tier 1 and decidable: a type list and a set of member names, all in the compilation.

The rule is only as good as the boundary exemptions, and the case it will get wrong is a factory
that does not look like one — a static member on some *other* type that builds the wrapper from a
primitive. `PositionFactory.FromLong(long)` is reported, and the honest answers are to move it onto
`Position` or to mark it `[DesignDecision(..., Scope = ExceptionScope.Boundary)]`, which is what the
scope is named for.

The other case is a surface that genuinely deals in a primitive: a logger taking a `string` message,
a hash returning `byte[]`. If that surface is a contract or a model type, the rule reports it and
the answer is usually that the member does not belong on that surface.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0013
```

No fix is registered. Introducing a wrapper means naming it, which is the design work, and a
generated `LongWrapper` would satisfy the rule while saying exactly as little as the `long` did.

## Violating example

```csharp
[assembly: DomainModel("Consumer.Model", typeof(CatalogShape.ModelNamespace))]

namespace Consumer
{
    [Contract(typeof(CatalogShape.ProductLookupContract), Role = "catalog read side")]
    public interface IProductLookup
    {
        long Read();
    }
}
```

```text
DD0013: the return type of 'IProductLookup.Read' is 'long'.
Decide: give 'long' a name: a readonly record struct wrapping it, so that two of them cannot be swapped and the surface says which is which | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
namespace Consumer.Model
{
    public readonly record struct Position(long Value)
    {
        public static Position Parse(string text) => new Position(long.Parse(text));
    }
}

namespace Consumer
{
    [Contract(typeof(CatalogShape.ProductLookupContract), Role = "catalog read side")]
    public interface IProductLookup
    {
        Position Read();
    }
}
```

`Position` names the `long` once, at the boundary, and nothing downstream can swap it for a count.
