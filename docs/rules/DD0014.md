# DD0014: A wrapper is a readonly struct with value equality

|  |  |
| --- | --- |
| **Id** | `DD0014` |
| **Tier** | 1 (error, mechanical, single compilation) |
| **Severity** | error |
| **Motivating decision** | `PrimitiveFreeSurfaces.WrappersAreReadonlyStructs` |
| **Introduced in** | unreleased |

## Principle

DD0013 asks for a wrapper. This is what stops the wrapper costing more than the thing it replaced.

## What the rule checks

A type in a `[DomainModel]` namespace with exactly one instance field, of a banned primitive type
(DD0013's list). Auto-properties count — an auto-property is a field with a name in front of it, and
a record struct's positional parameter is one too. A type with two fields is not a wrapper; it is a
small model type, and this rule has nothing to say about it.

Three faults, each with its own sentence:

- **A class.** Every one of them allocates, which is the cost the wrapper existed to avoid.
- **A struct that is not `readonly`.** A value that can change behind its holder's back.
- **A `readonly` struct with no value equality.** Two of the same value are not equal.

Value equality means a `record struct`, or `IEquatable<T>` of itself, or an `Equals(object)`
override. The `ValueType.Equals` a struct gets for free is not it: it boxes, it compares by
reflection or by bytes depending on the layout, and nobody chose it.

## Configuration

| Setting | Where | Default | Effect |
| --- | --- | --- | --- |
| `dd_banned_primitive_types` | `.editorconfig` | DD0013's list | What counts as the primitive being wrapped. |
| `ArchLayer` | MSBuild property | none | The rule runs only when this is set. |

Only `[DomainModel]` types are checked. A contract is not a wrapper, and an internal helper that
holds an `int` is how code is built rather than what it says.

## False-positive story

Tier 1 and decidable: one field count, one type kind, three symbol lookups.

The case that looks like a false positive and is not: a wrapper that is deliberately a class because
it is large or polymorphic. If it wraps one primitive it is neither, and the answer is a struct.
If there is a real reason — a cached instance, an identity that must be reference-equal —
`[DesignDecision]` on the type is where it is recorded.

The rule counts fields, so a wrapper with a second field added later silently leaves scope. That is
correct: it has stopped being a wrapper.

## Applying the fixes

`dotnet build` never runs a code fix, so a fix that only an IDE can reach is invisible to anyone
working from a terminal — an agent included. From a terminal:

```
dotnet format analyzers --diagnostics DD0014
```

No fix is registered. Turning a class into a struct changes how every holder of it behaves, and the
message already contains the declaration to paste.

## Violating example

```csharp
namespace Consumer.Model
{
    public sealed class Position
    {
        public long Value { get; }
    }
}
```

```text
DD0014: 'Consumer.Model.Position' wraps one 'long' and is a class, so every one of them allocates.
Decide: make it 'public readonly record struct Position(long Value)', or a readonly struct implementing IEquatable<T> with == and != | mark it [DesignDecision(typeof(<Set>.<Key>), Scope = ExceptionScope.<Scope>)] citing the accepted decision that says so.
Do not add the attribute without a decision that answers this; if the reason is only that the code already looked like this, take the design change.
```

## Conforming example

```csharp
namespace Consumer.Model
{
    public readonly record struct Position(long Value);
}
```

One line, no allocation, value equality, `==` and `!=`, and a `ToString` that says `Position { Value
= 12 }` rather than a type name.
