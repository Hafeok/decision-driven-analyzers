## Rulings made inside the prompt's scope

The prompt left these open. Each one is implemented as described and can be changed with a new
version of `MemoizedFieldsAreVerified`.

- **`[Memoized]` takes no decision argument**, unlike every other marker. It is a claim the rule
  checks, not a justification, so there is nothing to cite. `AttributesTakeOneDecisionType` says so.
- **Where the check runs.** Only in the classes DD0019's body check already covers: public model
  classes, not builders, and not a type marked `[DesignDecision]`. On any other field the attribute is
  inert and nothing reports it.
- **The value memo's writer may be any member**: private, an accessor or a constructor. A write
  in the constructor is "any other write", because neither accepted form is a plain assignment.
- **Correct forms the prompt did not list are reported** as "any other write":
  `if (h != 0) return h; h = …;`, `Interlocked.CompareExchange(ref …)`, and
  `field ?? (field = …)`.
- **Parameters are readable by a value memo's computation.** The prompt allows it. It means
  `Size(x) => size ??= x.Length` memoises whatever the first caller passed, and the rule accepts that.
- **The per-key factory body is not walked.** `static` already guarantees there are no captures. Its
  key and `arg` are held to the value memo's expression rule, so `this` as `arg` is refused as a capture
  by another route.
- **"In one member" applies to the per-key memo too.** Two members calling `GetOrAdd` with different
  factories would make a key's value depend on which ran first.
- **Reads on the dictionary** are DD0019's existing held-collection reads (through
  `IReadOnlyDictionary<K,V>`), plus `ToArray`, property reads, the indexer get and `foreach`. The
  dictionary returned or passed out as a value is its own finding.

## Questions

1. **A nested type writing the outer type's memo.** A nested class with a reference to an
   instance of the outer type can write its private `[Memoized]` field, and the check does not see
   it. Only the outer type's own members are scanned. The body check has the same blind spot for
   every field today, since it follows only writes through `this`, so this is not a regression. The
   options are (i) to leave it, or (ii) to scan nested types' bodies for writes to an outer memo.
2. **`[Memoized]` outside a model class.** The attribute is silently inert there. The options are
   (i) to leave it, (ii) a new diagnostic for a `[Memoized]` field DD0019 does not verify, or
   (iii) to verify it wherever `ArchLayer` is set. Option (ii) needs a new id, `DD0021`.
